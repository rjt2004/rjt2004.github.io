    3. 广播方向要对齐。max_logits 的形状是 (B, S)，直接和 (B, S, V) 相减时，PyTorch 会从最后一维往前对齐，把它当成 (1, B, S)，维度就错了；补一个 [..., None] 变成 (B, S, 1) 才是”每个位置减自己的最大值”。这与上一篇 softmax 里 keepdim=True 的道理完全一样。
    4. mean() 对所有位置一视同仁。真实训练中如果 batch 里有 padding，需要用 mask 把 padding 位置排除，否则会拉低平均损失；CS336 的 TinyStories 数据是定长切分，暂时不需要。

      实际工程里通常直接调用 torch.nn.functional.cross_entropy(logits.flatten(0, -2), targets.flatten())

    优化器

      有了损失，接下来要沿着损失下降的方向更新参数。梯度 指向损失上升最快的方向，所以往反方向走：

      其中 是从训练集里随机采样的一批数据， 是学习率。因为每步只用一小批样本估计梯度，所以叫随机梯度下降（Stochastic Gradient Descent, SGD）。

      优化器大致发展如下：SGD → Momentum → AdaGrad → RMSProp → Adam → AdamW。Momentum 用一阶动量抑制震荡；AdaGrad/RMSProp 用梯度平方的滑动平均给每个参数一套自适应步长；Adam 把动量和二阶矩结合并做偏差校正；AdamW 再把权重衰减从自适应步长里解耦。更完整的推导和直观讲解可以参考这个视频。

      下面先实现一个最基础的 SGD 变体，借它熟悉 PyTorch 优化器的 API；再实现现代大模型普遍使用的 AdamW；最后说明两个稳定训练的手段——学习率调度和梯度裁剪。

    SGD 与 PyTorch 优化器 API

      PyTorch 里所有优化器都继承 torch.optim.Optimizer，只要实现两个方法：

    • __init__(self, params, ...)：调用基类 super().__init__(params, defaults)，保存待优化参数和默认超参；
    • step(self)：执行一次参数更新，通常在 loss.backward() 之后调用。

      基类帮我们维护了两个关键容器：

    • self.param_groups：一个列表，每个元素是一组参数的字典（包含 params 和该组的超参）。分组的意义是不同层可以用不同学习率，比如微调时底层小、顶层大。
    • self.state：一个字典，以参数张量为 key，保存该参数自己的状态，比如迭代步数 t、一阶矩 m、二阶矩 v。

      可以把两个容器近似看成下面这样的结构。

    （1）param_groups：一个列表，每个元素是一组参数 + 一组超参

      如果只传 model.parameters()，列表里就只有一组，所有参数共用同一套超参；如果手动传入多个字典，就可以让不同层用不同 lr。step() 里按组遍历，读 group["lr"] 和 group["params"]，所以分组本质上是“一组参数 + 一组超参”。训练中改学习率，也就是改 group["lr"]。

    （2）state：一个字典，key 是参数对象，value 是该参数的状态

      如果是 SGD + Momentum，value 里通常只有 {"momentum_buffer": ...}；换成 AdamW，就变成 {"step": ..., "exp_avg": ..., "exp_avg_sq": ...}。每个参数的 m、v 都和该参数形状相同，所以参数量翻倍地占显存。

    • lr=1e1：因子约为 0.8 起步，损失平稳下降；
    • lr=1e2：前几步的更新因子绝对值接近 1，参数来回翻符号；随着学习率按 衰减， 这一步的更新因子正好变成 0，更新后参数被直接推到 0，后续损失塌到 0；
    • lr=1e3：更新步长远远超过参数本身，损失迅速爆炸。

      这个实验说明：学习率必须和参数初始化的量级、损失曲面的曲率匹配。太小收敛慢，太大震荡甚至发散，这也是后面要做 warmup 和余弦退火的原因。

    学习率调度

      让损失下降最快的学习率在训练过程中并不是常数。训练初期参数随机、梯度方向不稳定，一上来就用大学习率容易发散；训练后期已经接近一个好的区域，需要小学习率精细收敛。Transformer 的惯例是”先预热、再余弦衰减”：

    1. 线性预热：从 0 线性升到 ，让模型先”稳住”；
    2. 余弦退火：按余弦曲线从 平滑降到 ，两端平缓、中间下降较快；
    3. 保持最小学习率：超过 后不再下降，避免学习率变成 0 后完全停止学习。

      几个边界情况：

    • it=0 时返回 0，第一步不更新，这是 warmup 的常见做法；
    • it=T_w 时，预热分支结束、余弦分支开始，两边的值都等于 ，曲线连续；
    • it=T_c 时，余弦项 ，学习率正好降到 ；
    • 如果 warmup_iters=0，预热分支不会进入，直接从 开始余弦退火。

      实际配置里，max_lr 常取 1e-3 到 1e-4，min_lr 取最大值的 10% 左右，warmup_iters 取总步数的 1%～5%。这些值没有理论最优，需要结合模型大小、batch size 和数据量做超参搜索。

    梯度裁剪

      训练中偶尔会遇到”异常样本”：某个 batch 的损失特别大，反传回来的梯度范数可能是正常值的几十上百倍。哪怕只有一步，也可能把参数和 Adam 的 、 一起带偏，甚至直接导致 loss 爆炸。梯度裁剪的做法是给梯度的整体范数设一个上限 ：

      如果 ，说明梯度正常，不做任何处理。注意范数是对所有参数拼成的一个整体向量计算的，而不是每个参数张量各自算一次；否则每个张量都被单独裁剪，整体范数仍然可能很大。 取 PyTorch 默认的 1e-6，防止分母为 0，同时让裁剪后的范数略小于 。

      裁剪的位置很关键：必须在 loss.backward() 之后、optimizer.step() 之前。如果放在 backward() 之前，梯度还没算出来；如果放在 step() 之后，参数已经被异常梯度更新过了。PyTorch 也提供了 torch.nn.utils.clip_grad_norm_(model.parameters(), M)，实现逻辑与上面一致，工程里可以直接用。

      如果用了混合精度（AMP），梯度会先以缩放后的形式存在，裁剪前需要先 scaler.unscale_(optimizer)，否则算出来的范数是放大过的。这是后续做混合精度训练时要记得的一个坑。

    训练循环

      损失、优化器、学习率调度、梯度裁剪都齐了，但还差三件支撑设施：

    1. 数据加载：从一整条 token 序列里随机采样一批 (输入, 目标)；
    2. 检查点：把模型、优化器状态和迭代步数存到磁盘，训练断了能恢复；
    3. 训练循环：把前向、反向、更新、评估、日志串成一个可反复执行的循环。

    数据加载

      原始文本经过分词后，会变成一条很长的 token 序列 。不同文档之间通常插入 <|endoftext|> 作为分隔符，它也有自己的 token ID。数据加载器的任务，是从这条长序列里随机选 个起点，每个起点取长度为 的输入，以及整体右移一格的目标：

      目标就是输入右移一位：第 个位置要预测第 个 token。这样一条序列一次前向就能提供 个训练信号，不需要为每个位置单独切样本。

      图中 batch_size=2、context_length=3，随机抽到起点 1 和 4，于是输入是 [x1,x2,x3] 和 [x4,x5,x6]，目标分别是 [x2,x3,x4] 和 [x5,x6,x7]。不同样本之间可以重叠，这没有关系——每个样本只是从长序列里截取的一段窗口。

      几个细节：

    • **上界是 len(x) - context_length，不是 len(x)**。np.random.randint 的上界是开区间，所以起点最大是 len(x)-context_length-1，加上 L+1 个偏移后，最后一个下标正好是 len(x)-1。
    • starts[:, None] + offsets 是广播。(B,1) 加 (L+1,) 得到 (B,L+1)，每一行就是一个样本的连续窗口；再用这个二维索引去取 x，一次性取出整批，不需要 Python 循环。
    • **必须转成 torch.long**。嵌入层要求索引是 64 位整数，np.int32 或 np.uint16 直接转 tensor 会类型不匹配。
    • **大数据集用 np.memmap**。如果 token 序列有几个 GB，np.load(path, mmap_mode='r') 会把文件映射成”看起来在内存里”的数组，访问哪个窗口才加载哪一段磁盘内容，不会一次性占满内存。上面的花式索引只读取被选中的那几段，正好适合 memmap。

    检查点保存与加载

      训练可能被打断（机器重启、显存溢出、任务被抢占），也可能想拿中间模型做分析、对比不同阶段的生成效果。所以需要定期把训练状态存到磁盘。一个合格的检查点必须包含三样东西：

    1. 模型权重：model.state_dict() 返回全部可学习参数和 buffer（比如 RoPE 的 cos_table、sin_table），加载时用 load_state_dict() 装回去；
    2. 优化器状态：AdamW 的 、、 都在 optimizer.state_dict() 里，不恢复的话，续训时动量会从 0 重新开始，训练曲线会出现明显抖动；
    3. 迭代步数：记录走到哪一步，学习率调度和日志都依赖它。

      几个工程上的注意点：

    • **存 state_dict()，不要直接 torch.save(model)**。前者只保存张量和结构信息，不依赖类的定义，换代码、换目录都能加载；后者会把整个 Python 对象 pickle 进去，重构模型后经常加载失败。
    • map_location 不能省。在 GPU 上存的检查点拿到 CPU 上加载时，不加 map_location 会尝试分配 CUDA 显存并报错；反过来也一样。
    • 优化器状态是可选的。如果只是做推理，传 optimizer=None 即可，省一点加载时间；如果要续训，必须把优化器状态一起恢复。
    • 保存路径建议加上步数，比如 checkpoint_5000.pt，否则每次覆盖同一个文件，出问题后没有历史版本可回退。实际工程里还会用”临时文件 + 原子重命名”避免保存到一半断电导致文件损坏。

    组装完整训练循环

      推荐把训练拆成两层：train_step() 只负责一次参数更新，train_llm() 负责循环、调度、评估和存盘。这样单步逻辑可以单独测试，训练循环也不会太长。

      zero_grad() 的位置值得说明：PyTorch 的梯度是累加的，backward() 会把本步梯度加到 .grad 上，而不是覆盖。所以每次 backward() 之前必须清空上一次的梯度，否则相当于把多个 batch 的梯度加在一起，等效于放大了 batch size，学习率也要跟着改。放在 loss 计算之后、backward() 之前是可以的，因为此时还没有发生本步的反向传播；放在前向之前也常见，两种写法都对。

      验证集评估最好固定使用同一批窗口，比如训练开始前先采样好 val_x、val_y，之后每轮复用。否则每次 get_batch 都重新随机采样，验证损失会额外抖动，不同实验的曲线不好比较。

    优化器 SGD、AdamW 按梯度更新参数，AdamW 额外维护一阶矩、二阶矩
    学习率 learning_rate_schedule 线性 warmup + 余弦退火，前期稳、后期细
    稳定性 gradient_clipping 限制全局梯度范数，防止单步更新过猛
    数据 get_batch 从长 token 序列随机截取 (输入, 右移一格的目标)
    状态 save_checkpoint / load_checkpoint 保存模型、优化器状态和迭代步数
    循环 train_step / train_llm 把前向、反向、裁剪、更新、评估、存盘串起来

      几个容易混淆的点再强调一次：

    • 交叉熵先减最大值，再算 log-sum-exp，这不是近似，而是数学等价且数值稳定的写法；
    • AdamW 的权重衰减是解耦的，直接作用于参数，不经过自适应分母；
    • 梯度裁剪算的是全局范数，所有参数拼成一个向量，裁剪发生在 backward() 之后、step() 之前；
    • 检查点必须包含优化器状态和迭代步数，只存模型权重无法无损续训；
    • **训练和评估要切换 model.train() / model.eval()**，验证时包在 torch.no_grad() 里。

      有了这套循环，就可以在真实语料上训练模型，观察 loss 曲线、做超参搜索和消融实验，最后用训练好的检查点做自回归生成。接下来的实验会在 TinyStories 上把这条训练与推理解码的链路完整跑通。
